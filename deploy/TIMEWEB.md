# Установка на виртуальный хостинг Timeweb

Подходит, если у тебя уже есть хостинг с местом под сайт. Покупать VPS не нужно.
Нужен только домен и поддержка Python на тарифе.

## Что должно быть на тарифе

- **Свободный слот сайта** и доступ по **SSH**
- **Python 3.6 или новее.** В панели у сайта может стоять Python 3.4 —
  на нём код не запустится. На серверах Timeweb есть 3.10, версия
  переключается в настройках сайта (шестерёнка → версия Python).
- Бесплатный SSL Let's Encrypt — включается в панели в один клик

Сторонние библиотеки ставить не нужно: проект обходится стандартной
библиотекой Python. Ни pip, ни venv не требуются.

## Шаги

**1. Привязать домен.** Панель Timeweb → «Домены» → добавить домен и указать
его для сайта. Дождаться, пока он заработает по HTTP.

**2. Включить SSL.** Панель → «SSL-сертификаты» → выпустить бесплатный
Let's Encrypt для домена. Без HTTPS не работают микрофон (голосовой чат)
и установка сайта на телефон.

**3. Залить код.** Панель → «SSH-консоль», вставить одной строкой
(вместо `kotsaveli` — имя своего сайта из раздела «Сайты»):

```bash
bash <(curl -sL https://raw.githubusercontent.com/gladkihsava21-hash/english-cat/main/deploy/timeweb-setup.sh) kotsaveli
```

Скрипт сам найдёт папку сайта, сохранит копию того, что там лежало,
зальёт код, заведёт папку для базы и проверит, что приложение поднимается.
Запускать повторно можно — это же и обновление.

**4. Поднять версию Python.** Панель → «Сайты» → шестерёнка у нужного
сайта → выбрать **Python 3.10** (или любую от 3.6). На 3.4 сайт отдаст
ошибку 500: в коде используются f-строки, появившиеся в 3.6.

**5. Указать точку входа.** Там же, в настройках сайта:

- тип приложения: **WSGI**
- файл запуска: **wsgi.py**
- вызываемый объект: **application**

**6. Проверить.** Открыть `ТВОЙ-ДОМЕН.ru/health` — должно вернуться
`{"ok": true}`. Дальше сайт ученика на главной, панель — `/tutor.html`.

**7. Включить перенаправление на HTTPS** — в панели, после того как
сертификат выпущен. Раньше включать нельзя: браузер будет уходить
на https, которого ещё нет, и сайт станет недоступен.

## Где лежат данные

База создаётся сама в `~/ИМЯ-САЙТА/savely-data/savely.db` — рядом с
`public_html`, но **не внутри**. Это принципиально: внутри публичной папки
Apache отдал бы её по прямой ссылке вместе с хешами паролей и токенами.

Резервная копия — **не через `cp`**:

```bash
bash ~/kotsaveli/public_html/tools/daily-backup.sh kotsaveli
```

Почему не `cp`. База работает в режиме WAL: свежие записи какое-то время
лежат не в `savely.db`, а рядом, в `savely.db-wal`. Скопировали один
файл — получили базу без последних изменений, а иногда и вовсе пустую.
Проверить это можно только тогда, когда копия понадобится, то есть
слишком поздно.

`daily-backup.sh` делает согласованный снимок (`.backup`), проверяет,
что копия читается, и держит семь файлов по дням недели. Ставится
в расписание один раз: панель Timeweb → Crontab → каждый день в 4:00.

Делай копию и перед каждым обновлением — файл маленький, места не жалко.

## Обновление сайта

Та же команда, что и при установке:

```bash
bash <(curl -sL https://raw.githubusercontent.com/gladkihsava21-hash/english-cat/main/deploy/timeweb-setup.sh) kotsaveli
```

Папку `savely-data/` она не трогает — прогресс учеников остаётся на месте.
После обновления в панели нажать «Перезапустить приложение».

## Права на файлы

Заливка по SSH оставляет права по умолчанию (`umask 077`), и Apache не может
прочитать файлы — сайт отдаёт 403. Скрипт установки выставляет их сам, но если
заливал вручную:

```bash
cd ~/ИМЯ-САЙТА/public_html
find . -type d -exec chmod 755 {} +
find . -type f -exec chmod 644 {} +
chmod 700 ../savely-data
```

## Если что-то не работает

| Симптом | Причина |
| --- | --- |
| 500 на всех страницах | Не выбран callable `application`, не тот файл запуска, либо остался Python 3.4 |
| `/health` отдаёт 403, сайт при этом открывается | Обработчик Python не включён для сайта — панель → «Сайты» → шестерёнка |
| 403 на всех страницах | Права на файлы: нужны 755 на папки и 644 на файлы |
| Панель репетитора пустая | Приложение не запущено — проверь `/health` |
| Стили поехали | Старый кэш: нажать Ctrl+Shift+R |
| «Не защищено» в браузере | Не выпущен SSL |

Логи ошибок — в панели, раздел «Логи», файл `error.log`.

## Включить ИИ — Алиса (Яндекс)

Без ключа сайт работает: Савелий отвечает по правилам, фото домашки уходит
репетитору без разбора. С ключом включаются умный чат (YandexGPT) и
проверка тетрадей (Яндекс OCR распознаёт рукописный текст, YandexGPT
разбирает ошибки). Данные при этом остаются в России — уведомление о
трансграничной передаче не нужно (см. RKN.md).

Что сделать один раз в Yandex Cloud (console.yandex.cloud, карта РФ
принимается, оплата по факту):

1. Создать платёжный аккаунт и каталог (folder) — идентификатор каталога
   выглядит как `b1g…`, он понадобится.
2. Создать сервисный аккаунт, выдать ему роли **ai.languageModels.user**
   и **ai.vision.user**.
3. Для сервисного аккаунта создать **API-ключ** (не OAuth): строка `AQVN…`.

Потом положить файл рядом с базой — **вне публичной папки**:

```bash
cat > ~/ИМЯ-САЙТА/savely-data/yandex.conf <<CONF
api_key = AQVN...ваш ключ...
folder = b1g...ваш каталог...
CONF
chmod 600 ~/ИМЯ-САЙТА/savely-data/yandex.conf
```

И в панели нажать «Перезапустить приложение». Проверка: в логах при старте
строка «Алиса (Яндекс) настроена», в админке сверху «ИИ: Алиса».

Модели по умолчанию: чат — `yandexgpt-lite/latest` (лёгкая и дешёвая,
~0,2 ₽ за сообщение), разбор домашек — `yandexgpt/latest` (умная, вместе
с OCR ~1,5 ₽ за тетрадь). Поменять можно строками `chat_model = …` и
`check_model = …` в том же yandex.conf.

Файл лежит вне `public_html`, скрипт обновления его не трогает.

### Запасной вариант — Claude (Anthropic, США)

Работает так же: `echo 'sk-ant-КЛЮЧ' > ~/ИМЯ-САЙТА/savely-data/api_key.txt`
и перезапуск. Если есть ОБА ключа, фото и чат идут через Claude.
**Но**: это трансграничная передача — сначала уведомление в РКН по ст. 12
и письменные согласия родителей (см. RKN.md, раздел Б). Карты РФ Anthropic
не принимает.
