# Переезд wordcat.ru на VPS — план и роли

Причина: 4 падения shared-хостинга Timeweb за 10 дней (11–14.09.2026),
сайт лежал часами, статика отдавалась 6–9 КБ/с. Бонусы переезда:
свой nginx (сжатие, честные кэш-заголовки), позже — WebSockets вместо
полинга доски и TURN для 100% дозвона видеоурока.

## Что покупает владелец (10 минут)

Timeweb Cloud (та же учётка, тот же ЛК, домен уже там) → «Облачные
серверы» → создать:
- Ubuntu 24.04, 1×CPU / 2 ГБ RAM / 30 ГБ NVMe (~350 ₽/мес) — хватит
  с запасом, наш сервер — stdlib-python + SQLite;
- при создании добавить SSH-ключ (или получить root-пароль).

Прислать напарнику-агенту: IP сервера и доступ (root-пароль или
подтверждение, что публичный ключ с мака добавлен).

## Что делает агент дальше (по шагам, ~час)

1. `ssh root@IP` → `bash <(curl -sL https://raw.githubusercontent.com/gladkihsava21-hash/english-cat/main/deploy/vps-setup.sh)`
   — nginx, systemd, код, файрвол, крон бэкапов.
2. Кладёт свежий снимок базы (`~/english-cat/backups/savely-*.db`,
   спасён с shared) в `/opt/wordcat/data/savely.db`, рестарт.
3. Проверка по IP: `curl http://IP/health`, прогон логина/доски.
4. **Стоп-момент — согласовать с владельцем время** (вечер, когда нет
   уроков): в ЛК Timeweb сменить A-запись wordcat.ru (и www) на IP VPS.
   TTL у Timeweb 600 сек → переключение ≤10 минут.
5. Как только DNS доехал: `certbot --nginx` — HTTPS с автопродлением.
   (HSTS уже включён на клиентах — потому TLS ставим сразу же.)
6. Финальная сверка базы: за окно переключения на shared могли писать —
   снять снимок ещё раз и слить поверх, если shared жив.
7. Shared-хостинг НЕ отключать месяц (пусть будет откат), потом закрыть.

## Что меняется в ежедневной работе

- Деплой: `bash deploy/vps-deploy.sh root@IP` (бэкап → pull → restart).
- Бэкапы: ежедневно 04:00 на сервере, 14 штук по кругу;
  раз в неделю забирать копию на мак (`scp`).
- Мониторинг: /health как раньше.
