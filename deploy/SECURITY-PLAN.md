# План усиления безопасности wordcat.ru

Составлен 13.09.2026 по итогам аудита поверхности атаки (12 агентов, 6
линз, каждая находка воспроизведена и проверена скептиком). Цели
владельца: в админку посторонним «вообще не попасть»; неоплату «никак не
обойти»; данные детей защитить и от постороннего, и от неплатящего
репетитора.

Всего подтверждено: **8 высоких, 8 средних, 7 низких.** Ложных — 0.
Многие находки — одна причина; ниже сгруппировано по РАБОТЕ, не по числу
находок.

## Архитектура, важная для починок

Бой: **nginx/1.30.4 → Apache + mod_wsgi**. Следствия:
- Заголовки безопасности надо ставить в Python-ответе (переживут nginx)
  И в `.htaccess`, и потом ПРОВЕРЯТЬ curl'ом, что дошли.
- `REMOTE_ADDR`, который видит mod_wsgi, — это адрес nginx, не клиента.
  Настоящий IP клиента nginx кладёт в `X-Real-IP`. Спуфится ли он
  клиентом — зависит от того, перезаписывает ли nginx заголовок
  (`proxy_set_header X-Real-IP $remote_addr`). Проверяется эмпирически.
- Крипто на сервере есть: openssl 3.0.2, gpg, zip -e, python 3.10.

## A. Админка — «вообще не попасть»

1. **X-Real-IP / доверие к заголовку (wsgi.py:176).** who берётся из
   `HTTP_X_REAL_IP or REMOTE_ADDR` без проверки источника. Чинить: брать
   `X-Real-IP` ТОЛЬКО когда `REMOTE_ADDR` = известный upstream nginx;
   иначе `REMOTE_ADDR`. Это чинит и обход замка админки, и обход всех
   лимитов частоты одним изменением. Плюс глобальный потолок неудачных
   попыток админ-логина (смена ключа не даёт чистый счётчик).
2. **TOTP (Google Authenticator) вторым фактором на админ-логин.** Чистый
   stdlib (hmac-sha1). Даже подобранный/утёкший пароль без 6-значного
   кода не пускает. Владелец сканирует QR один раз.
3. **admin.txt открытым текстом → хеш пароля + секрет TOTP** в файле вне
   webroot. pbkdf2, как у паролей репетитора.
4. **admin.html — с известного пути на секретный;** убрать /admin.html и
   /tutor.html из robots.txt (сейчас robots сам указывает вход).
5. **Форсить HTTPS + HSTS** (сертификат выпущен — https отвечает).
6. **admin-сессия:** TTL короче, ротация, привязка.

## B. Неоплата — «никак не обойти»

7. **Все runtime-ручки репетитора мимо verified_tutor.** board_sync,
   call_*, book_page, lesson_open/set, notify_set, photo_fetch
   (репетиторская ветка) — берут токен напрямую, на expired не проверяют
   оплату. Централизовать helper `tutor_paid()` и прогнать все.
   Закрывает: живой урок без оплаты, чтение фото тетрадей детей, набор
   учеников (student_join/adopt через can_add_student).
8. **Ученические ИИ-ручки — по оплате репетитора.** chat, tts,
   photo/use_check: перед вызовом провайдера смотреть access_state
   репетитора ученика. На expired — урезанный режим: **1 упражнение в
   день + «сдать домашку», без ИИ** (решение владельца). Платящие сами
   ученики (будущая подписка) на неоплате — полный замок.
9. **Гостевой чат жжёт Claude (server.py:2445).** Витрина открыта без
   токена. После починки X-Real-IP лимит по IP становится реальным;
   плюс жёсткий кап размера промпта и дневной кап.
10. **Бесконечный триал (deviceId/IP из тела).** Слабый антифрод.
    Митигация: не доверять deviceId вслепую, завязать на подтверждённую
    почту, снизить порог по РЕАЛЬНОМУ ip. (Скептик срезал severity: без
    доступа к данным и деньгам — свежий кабинет пуст, ИИ на паузе.)

## C. Данные — от постороннего и от неплательщика

11. **SESSION.md / AGENTS.md отдаются наружу (HTTP 200).** `.htaccess`
    FilesMatch не покрывает `.md`. Закрыть `.md|.markdown|.sh|.txt|.conf|
    .bak`, проверить curl'ом; долгосрочно — не деплоить dev-доки.
12. **Ни одного заголовка безопасности.** CSP, HSTS, X-Frame-Options:
    DENY, X-Content-Type-Options: nosniff, Referrer-Policy — в Python и
    .htaccess, проверить, что nginx пропускает.
13. **Recovery-код вечен и не тратится.** set_tutor_password его не
    трогает. Ротировать при смене пароля, гасить использованный,
    /api/tutor/password/reset в лимиты.
14. **Токены без срока и без отзыва.** Ученический токен не убивается
    сменой пароля/кода. Добавить idle-TTL (щедрый, чтобы не разлогинить
    Ирину среди недели), ротацию при смене пароля, «выйти везде».
15. **Копии базы — открытым текстом.** Шифровать openssl/gpg паролем
    владельца (daily-backup.sh).
16. **Мелочи:** errors хранит IP+id+трейсбек (усечь ввод в message);
    CORS `*` сузить; robots не палит пути; листинг каталогов.

## Порядок работ

1. **Батч 1 (безопасно, без влияния на живых):** утечка файлов, заголовки
   безопасности, robots, HTTPS-редирект. + эмпирическая проверка
   спуфа X-Real-IP на бою.
2. **Батч 2 (paywall):** helper `tutor_paid()`, прогон runtime-ручек,
   ученические ИИ по оплате, урезанный режим.
3. **Батч 3 (админка):** X-Real-IP fix, TOTP, хеш пароля, секретный путь.
4. **Батч 4 (токены/данные):** recovery-код, TTL/ротация токенов,
   шифрование бэкапов.
5. **Ред-тим воркфлоу:** параллельные атакующие ломают каждую починку
   (спуф заново, обход paywall, подделка TOTP). Что сломают — чиним.

Каждый батч: правка → тест (jsdom/python-харнесс, воспроизведение ДО и
ПОСЛЕ) → деплой в окно связи → проверка снаружи.

## Требует владельца

- Завести TOTP в Google Authenticator (сканирует QR при первом входе).
- Сохранить пароль для шифрованных бэкапов (иначе копию не открыть).
- Знать новый секретный адрес админки.
