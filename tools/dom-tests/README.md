# Прогон упражнений в настоящем DOM

Проверяет то, что `node --check` не видит: поведение. Грузит `index.html`
со всеми скриптами в jsdom, подсовывает вошедшего ученика и играет
упражнения кликами — как ребёнок.

Именно этим прогоном найдены пять багов, каждый из класса «тренажёр
незаметно врёт ученику»: засчитанные слова без ответа, раунд, закрытый
дважды («Верно 7 из 6»), очки за повторное нажатие. Такие вещи не видны
при чтении кода: каждая функция по отдельности верна.

## Запуск

Зависимость одна и ставится руками — в репозитории `node_modules` нет
принципиально:

```bash
cd tools/dom-tests && npm install jsdom
./run-all.sh              # всё подряд; ненулевой код возврата, если что-то упало

node test-smoke.js        # все упражнения открываются и прокликиваются
node test-irr.js          # неправильные глаголы, подробно
node test-fixes.js        # «Свои предложения», «Собери слово», ленивые банки
node test-double.js       # кроссворд и «Колесо»: повторные нажатия
node test-invariants.js   # счёт: подход не закрывается дважды, верных не больше заданий
```

## Случайность предсказуемая

Упражнения тасуют слова, варианты и сетку кроссворда, поэтому раньше один
и тот же тест то проходил, то нет. Мигающий тест хуже отсутствующего: к
нему привыкают и перестают читать. Теперь `Math.random` в стенде — свой
генератор с зерном, и любой прогон повторяется:

```bash
SEED=42 node test-double.js
```

Зерно по умолчанию фиксировано. Если тест проходит только на нём — он
проверяет удачу, а не код; прогони на нескольких.

## Проверка «а был ли баг»

Починку легко перепутать с починкой того, чего не было. Поэтому те же
тесты умеют прогоняться на версии ДО правок:

```bash
git show <коммит>:js/exercises.js > exercises-old.js
git show <коммит>:js/games.js     > games-old.js
OLD_EX=1 OLD_GAMES=1 node test-double.js   # должно ПРОВАЛИТЬСЯ
node test-double.js                        # должно пройти
```

Если на старом коде тест проходит — значит баг придуман, а не найден.

## Швы для тестов

Стенд подменяет ровно три вещи, и каждую по делу:

- `readGateMs` → 0. Пауза на чтение защищает от прокликивания живого
  ученика; тесту она мешает, а проверяет он не её.
- `MQ.matches` (см. `harness-full.js`) включает `prefers-reduced-motion`.
  Колесо тогда сразу встаёт на слове — это штатный путь игры для
  человека, отключившего анимации, а не «ускорение для теста».
- `exFinish` / `statUpdate` / `award` оборачиваются счётчиками, чтобы
  видеть, сколько раз упражнение засчитало ответ.

Речи (`speechSynthesis`) в jsdom нет вовсе, поэтому `TTS_OK` сам
становится false — аудио-упражнения идут по своей штатной ветке.

## Чего стенд НЕ проверяет

Вёрстку, попадание пальцем, звук, реальную сеть. Он про логику: что
засчитано, сколько раз и кому. Внешний вид смотри в браузере.
